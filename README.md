# 榆巷纸样工坊

制版台交付双面格稿。纸样员冻结原件，校样员在浏览器里按折步检查两侧，印务员用展开图和已签校样单找到需要改动的原纸面。应用使用 Python 3.11 标准库和 SQLite。

## 打开工坊

在项目目录运行。

```sh
python3 -B -m sheet.intake --db workshop.sqlite3 examples/double_fold.json
python3 -B -m browser.http_server --db workshop.sqlite3 --port 8000
```

导入命令输出校样号。用浏览器打开 `http://127.0.0.1:8000/`，输入该号。在折步 2 分别打开正看和反看页，从两页的唯一可见格各写一笔批注。每笔回执都会给出原纸位置。再打开展开图核对，按「签出校样单」保存，之后可从首页按签出号领取。服务器仅监听本机。可另行导入 `examples/unfolded_faces.json` 查看未折的三列纸样。

重新启动服务会保留已有记录。启动时只创建缺失的表。每次显式导入都会生成独立校样号，编辑原 JSON 文件不会改变已经冻结的校样。已签单保留签出当时的批注明细，之后新增的批注出现在后续签出的单上。

## 格稿和折叠口径

- `width`、`height` 为正整数。`front`、`back` 是 `{ "x": 0, "y": 0, "mark": "图记" }` 记录的数组，`holes` 是 `[x, y]` 坐标的数组。各面图记和孔分别禁止重复格。正背面使用同一套原纸坐标，列从左到右，行从上到下，从 0 起算。图记可省略某格，空白实纸仍可写批注。孔上图记随原件保留，预览中透过该层。
- `folds` 为最多两个 `{ "axis": "x", "line": 2, "moving": "high" }` 项的有序数组。`axis` 可为 `x` 或 `y`，`moving` 可为 `low` 或 `high`。第 0 步是原纸。每步的格线必须沿当前投影范围的内部格边。沿 k 折叠时把低侧 `i < k` 或高侧 `i >= k` 移到 `2k-1-i`。两侧可不等长，投影可越出原纸。
- 移动整叠倒序、翻面并盖到静止叠上。正看和反看从各自一侧穿过孔层，遇到的第一层实纸决定可见面。显示格在当前范围内从 0 起算。反看镜像列序，行序与正看一致。展开图两面的标签都是原纸坐标。
- 双折格稿从左到右为 A、B、C、D，B 贯穿镂空。沿 x=2、x=1 依次将高侧叠向低侧，正看从 B 孔看到 C 正面，反看最先遇到 A 背面。将 B 改为实纸，正看变为 B 背面。全部镂空时显示空处，服务端拒绝对该处的批注。

## 交接入口

| 入口 | 请求与成功结果 | 失败结果 |
| --- | --- | --- |
| `python3 -B -m sheet.intake --db DB FILE` | 导入 JSON 并输出冻结校样号 | 非零退出，无新校样 |
| `GET /proofs/{id}?step=0&side=front` | 打开预览，`side` 可选 `front` 或 `back` | 非法视图 400，未知校样 404，无选格表单 |
| `POST /annotations` | URL 编码的 `proof_id, step, side, x, y, text`，201 回执包含批注号与原纸面 | 无法解析 400，未知校样 404，空处 422，无新批注 |
| `GET /proofs/{id}/unfolded` | 按原纸格和纸面展开展示批注 | 未知校样 404 |
| `POST /reports` | URL 编码的 `proof_id`，201 返回已提交的快照和签出号 | 未知校样 404，签存失败 500，均无新单 |
| `GET /reports/{id}` | 凭签出号领取原签快照 | 未知签出号 404 |

## 分步试裁签单

冻结校样另有一份共享纸况，只记录成功签出的试裁单新增的裁口。原稿通孔始终在底层。试裁台与草稿入口见 `CUT_PLANS.md`。

| 入口 | 请求与成功结果 | 失败结果 |
| --- | --- | --- |
| `GET /proofs/{id}/cut-plans?step=&side=` | 显示共享纸况和开稿表单 | 非法视图 400，未知校样 404 |
| `POST /cut-plans` | URL 编码的 `proof_id`，201 显示新草稿 | 未知校样 404 |
| `GET /cut-plans/{id}?step=&side=` | 显示草稿、已有步骤和本页选格表单 | 非法视图 400，未知草稿 404 |
| `POST /cut-plans/{id}/steps` | `revision, step, side, x, y`，200 追加一步 | 过期表单 409，无实纸 422，未知草稿 404 |
| `POST /cut-plans/{id}/issue` | `revision`，201 显示已签试裁单 | 过期表单 409，纸况冲突 409（指出步号），未知草稿 404，签存失败 500 |
| `GET /cut-reports/{id}` | 按试裁单号领取原签内容 | 未知号 404 |

草稿从开启时的共享纸况起步，此后沿自己的步骤推进；其他草稿签出时已开草稿仍显示原审阅结果。每一步贯穿该视向所见第一张实纸，并预览裁后本格露出的原格与纸面，无纸可露时明示露空。签出按草稿步骤顺序逐步验口：原格已是孔时记「先前完成」并核对当下露面，仍是实纸时须仍见所审原面才新增裁口，每步办完核对露面后才办下一步。冲突或签存失败都不新增裁口或签单。

浏览器选格表单始终带该页的校样、折步、视向和显示格。服务端据此从冻结原件重算落点。批注保留填写的非空原文。展开与签出都读取已持久化的原面身份。

## 回归和演示

```sh
python3 -B check_project.py
```

标准入口由控制台随工程提供。可直接运行完整 unittest 套件及双折演示。

```sh
python3 -B -m unittest discover
python3 -B -m unittest tests.test_browser.BrowserTests.test_two_sided_fold
python3 -B -m unittest tests.test_cut_plans
python3 -B -m cut.demo
```

演示在临时数据库和本机临时端口运行。它打开正反两页，先反后正提交实际渲染的表单，核对两笔原纸面回执及展开和签出内容，随后打印 `POINTWISE_SCENARIO` 实测记录。完整套件另检查冻结失败、旧页折步、空白实纸、全孔无写入、签存回滚、重开及历史领取。
